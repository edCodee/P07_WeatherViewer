# Weather Viewer — Catálogo de correcciones (PDF Deitel 2016 → Android 16 / API 36)

Proyecto: compileSdk 37, targetSdk 36, minSdk 24. AGP 9.4.1, Gradle 9.6.0.
Contrato del API medido el 2026-09-23: [api/CONTRATO.md](api/CONTRATO.md).

> **Numeración.** El código cita `bug #6`, `#12`–`#15` e `incompatibilidad #10` y `#17`: esos números conservan aquí su significado. Los demás se asignaron en esta documentación. **→ §7 #n** remite a [ANALISIS_DISENO.md](ANALISIS_DISENO.md), sección 7.

## Plataforma y build

| #   | PDF                                                                             | Problema actual                                            | Corrección                                                                                                                    |
| --- | ------------------------------------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 1   | Java                                                                            | Kotlin es el lenguaje recomendado                          | Todo en Kotlin                                                                                                                |
| 2   | `android.support.v7`, `android.support.design` (FAB, Snackbar, TextInputLayout) | Support Library descontinuada                              | AndroidX + Material Components 1.14                                                                                           |
| 3   | `AsyncTask` (7.3.4, Figs. 7.13 y 7.18)                                          | Obsoleto desde API 30; retiene la Activity y no se cancela | Corrutinas: `viewModelScope` en el ViewModel, `withContext(Dispatchers.IO)` en los repositorios, `lifecycleScope` para íconos |
| 4   | Java SE 7 configurado a mano (7.4.1 → 4.4.3)                                    | Obsoleto                                                   | Java 11 en `build.gradle.kts`                                                                                                 |
| 5   | Plantilla Blank Activity con `content_main` incluido y FAB abajo a la derecha   | La plantilla ya no existe                                  | Un solo `activity_main.xml` con `CoordinatorLayout` (ancla del Snackbar, 7.4.5 paso 1)                                        |

| 6   | `Snackbar.make(findViewById(...))` dentro de `doInBackground` (Fig. 7.18 ll. 129, 137, 142)                                        | Toca vistas desde un hilo de fondo                                                                                                                                  | **Bug #6.** El error viaja en el estado y el Snackbar se muestra en `render()`, en el hilo principal y solo con la pantalla en `STARTED`                                                             |
| 7   | API key en `strings.xml` (7.3.1, Fig. 7.4)                                                                                         | Queda publicada en el repositorio                                                                                                                                   | `local.properties` (ignorado por Git) → `BuildConfig.OWM_API_KEY`; el build no falla sin key → §7 #7                                                                                                 |

| 9   | `forecast/daily?q=ciudad`                                                                                                          | El geocoding integrado por nombre está en desuso                                                                                                                    | `/geo/1.0/direct?q=…&limit=1`; una ciudad inexistente responde **200 con `[]`**, no con error (CONTRATO, archivo 04)                                                                                 |

| 11  | `units=imperial` y `"°F"` concatenado en `Weather` (Fig. 7.7)                                                                      | Unidad fija para todo el mundo                                                                                                                                      | Dominio en °C (`units=metric`); °C o °F según `LocalePreferences.getTemperatureUnit()`                                                                                                               |
| 12  | `convertTimeStampToDay` con la zona del **teléfono** y `calendar.add(tz.getOffset(...))` (Fig. 7.8)                                | El día depende de dónde está el teléfono y no la ciudad; además, `SimpleDateFormat` ya formatea en la zona del teléfono, así que el desfase se aplica **dos veces** | **Bug #12.** Agrupación por día local de la ciudad (`city.timezone`); el nombre del día se formatea en UTC sobre ese `epochDay`                                                                      |
| 13  | `Map<String, Bitmap> bitmaps = new HashMap<>()` escrito en `doInBackground` (Fig. 7.13 l. 122)                                     | Un `HashMap` escrito desde varios hilos y leído en el principal; además, sin límite                                                                                 | **Bug #13.** `IconCache` LRU (32 entradas), usado solo desde el hilo principal                                                                                                                       |
| 14  | `LoadImageTask` guarda el `ImageView` de la fila (Fig. 7.13)                                                                       | Si la fila se recicla antes de que llegue el ícono, muestra el de otro día                                                                                          | **Bug #14.** `ImageLoader` cancela la carga anterior del mismo destino; probado con descargas que llegan en desorden                                                                                 |
| 15  | `weatherList` y la `AsyncTask` en la Activity; orientación bloqueada                                                               | Rotar, cambiar el tema o el idioma pierde el pronóstico                                                                                                             | **Bug #15.** `ForecastViewModel` con `StateFlow`; prueba instrumentada `recrear_la_activity_conserva_el_pronostico`                                                                                  |
| 16  | Si la petición falla, `doInBackground` devuelve `null` y `onPostExecute` llama a `convertJSONtoArrayList(null)` (Fig. 7.18 l. 156) | `forecast.getJSONArray` sobre `null`: `NullPointerException`, la app se cierra                                                                                      | `ForecastResult` sellado: el caso de uso nunca devuelve `null` ni lanza errores de negocio                                                                                                           |
| 17  | Solo `connect_error` y `read_error`; 401, 404 y "ciudad inexistente" se confunden                                                  | El usuario no sabe qué hacer                                                                                                                                        | **Incompatibilidad #17.** Seis fallos tipados (`EmptyQuery`, `CityNotFound`, `Unauthorized`, `NoConnection`, `ServiceUnavailable`, `UnexpectedResponse`), cada uno con su mensaje; `when` sin `else` |
| 18  | `InputMethodManager` con cast de `getSystemService` (7.7.4)                                                                        | Verboso y frágil                                                                                                                                                    | `WindowCompat.getInsetsController(...).hide(ime())`                                                                                                                                                  |
